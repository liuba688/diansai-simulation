# 2024 H 题复现：要求（4）

> 当前状态（2026-07-26）：程序与 HEX 已生成，Keil 编译 0 错误、0 警告；尚未进行第四题四圈实车测试。

## 当前实现范围

- 路线：A → C → B → D → A，连续运行 4 圈。
- A → C：直行，离开 A 点黑线后持续寻找 C 点黑线。
- C → B：使用根目录 `project` 中更新前的八路数字灰度巡线。
- B 点：检测到弧线末端后，不使用 MPU，按固定时间进行左右轮差速转向。
- B → D：转向结束后直行，持续寻找 D 点黑线。
- D → A：重新进入旧版巡线；前三圈到弧线末端后进入下一圈，第 4 圈停车。
- 前 3 圈到达 A 后，以与 B 点相同的 54 RPM 轮速差反向转弯，再开始下一圈；第 4 圈到达 A 后停车。
- 当前不使用 MPU，不做角度闭环，也不做声光提醒。
- 蓝牙命令保持不变：`1`/`START` 启动，`0`/`STOP` 急停。

巡线部分已按实车反馈回退为更新前版本：灰度数据直接单次采样并计算八路加权误差，不再使用 3 帧多数滤波、连续黑块筛选、置信度判断以及误差/微分低通。

丢线处理改为低速直行前探：暂时检测不到黑线时，两轮以 32 RPM 继续直行约 150 ms；期间重新找到黑线就立即恢复巡线，持续找不到才确认到达线端。C → B 段确认线端后进入 B 点差速转向；D → A 段确认线端后，前三圈在 A 点转向，第四圈停车。

## 状态编号

| OLED/UART 编号 | 状态 |
|---:|---|
| 0 | 等待启动 |
| 1 | A → C 直行找线 |
| 2 | C → B 巡线 |
| 3 | B 点定时差速转向 |
| 4 | B → D 直行找线 |
| 5 | D → A 巡线 |
| 6 | A 点转向，准备下一圈 |
| 7 | 四圈完成并停车 |

启动后仍保留 3 秒安全等待。直行找线阶段必须先连续检测到白场，再连续检测到黑线，避免把出发点 A/B 的黑线误认为 C/D。

## 优先实车调整

参数集中在 `project/user/src/main.c` 顶部：

- `ROUTE_SEARCH_RPM`：两段直行速度，当前 55 RPM。
- `ROUTE_TURN_LEFT_RPM`：B 点转向时左轮速度，当前 28 RPM。
- `ROUTE_TURN_RIGHT_RPM`：B 点转向时右轮速度，当前 82 RPM；与左轮相差 54 RPM。
- `ROUTE_TURN_TICKS`：差速转向时间，当前 100 × 10 ms = 1.0 s。
- `ROUTE_LINE_CONFIRM_TICKS`：找到黑线的连续确认次数。
- `ROUTE_LOST_CONFIRM_TICKS`：离开黑线/到达弧线末端的连续确认次数，当前 15 次，即约 150 ms。

丢线前探速度和时间也可在 `project/code/line_follow.h` 中调整：

- `LINE_FOLLOW_LOST_FORWARD_RPM`：前探速度，当前 32 RPM。
- `LINE_FOLLOW_LOST_FORWARD_TICKS`：前探周期数，当前 15。

当前默认在 B 点向左转。如果实车转向相反，交换 `ROUTE_TURN_LEFT_RPM` 与 `ROUTE_TURN_RIGHT_RPM` 的数值。先架空轮子检查左右轮方向，再从低速、短转向时间开始落地调整。

## 起始摆放

将车放在 A 点，车头直接朝向 C 点。灰度传感器允许起始时压在 A 点附近黑线上；程序会先等车辆进入白场，再开始识别 C 点。
