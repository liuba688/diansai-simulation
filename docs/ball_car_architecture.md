# 循迹寻球小车架构与状态机

## 1. 功能边界

当前方案只使用两块计算控制设备：

```text
MaixCAM：钢珠检测、时序跟踪、主目标选择
    │ UART 115200，目标坐标/大小/置信度
    ▼
MSPM0G3507：状态机、循迹、接近控制、速度闭环、电磁铁控制
    │
    ├─ TB6612 + 双编码器电机
    ├─ YB-MVX05 八路灰度
    └─ 外置 MOSFET + 电磁铁
```

MaixCAM 不直接控制电机。它只发送视觉测量值，所有安全状态、运动决策和执行都由 MSPM0G3507 完成。这样即使视觉帧丢失或应用退出，MSPM0 也能在 200 ms 超时后判定链路失效。

## 2. 软件模块

### MSPM0G3507

| 文件 | 职责 |
|---|---|
| `car_app.c/.h` | 顶层初始化、10 ms 调度、命令处理、状态整合 |
| `ball_car.c/.h` | 寻球取球状态机和轨迹记录/倒放 |
| `vision_uart.c/.h` | UART2 中断接收、环形缓冲、链路超时与状态回传 |
| `vision_protocol.c/.h` | 帧解析、CRC8、数据编解码 |
| `magnet_driver.c/.h` | PB10 外置 MOSFET 逻辑控制 |
| `line_follow.c/.h` | 已验收的灰度循迹逻辑 |
| `line_sensor.c/.h` | 八路灰度读取与位置误差 |
| `speed_pid.c/.h` | 双轮速度 PI |
| `tb6612.c/.h` | 双路电机驱动 |
| `wheel_encoder.c/.h` | 双编码器四倍频计数 |

`main.c` 只调用 `car_app_init()` 和 `car_app_run()`，不承载具体业务逻辑。

### MaixCAM

| 文件 | 职责 |
|---|---|
| `main.py` | 相机、模型推理、显示、UART 调度 |
| `ball_tracker.py` | 候选过滤、多帧匹配、稳定目标选择 |
| `vision_uart.py` | MaixPy UART1 初始化、发送目标、接收小车状态 |
| `vision_protocol.py` | 与 MSPM0 完全对应的二进制协议 |
| `config.py` | 模型阈值、跟踪、接近判断和 UART 参数 |

视觉端将“显示阈值”和“控制阈值”分开：达到 50% 且连续稳定 3 帧的目标显示红框，并让小车保持灰度循迹但把左右轮实时输出同时降低到三分之一；达到 60% 且连续稳定 5 帧后显示绿框，TI 在收到绿框的当前控制周期立即停车、开启电磁铁并进入寻球锁定。

## 3. 状态机

控制周期为 10 ms。

| 状态 | 主要行为 | 退出条件 |
|---|---|---|
| `IDLE` | 电机停车；若未持球则关闭电磁铁 | 收到启动命令并完成 3 s 延时 |
| `LINE_FOLLOW` | 无框时使用原巡线输出；红框时把左右轮巡线输出同时乘以 `1/3` | 绿框出现时立即停车、开启电磁铁并进入锁定 |
| `TARGET_CONFIRM` | 只保留旧状态编号兼容，新流程不再进入 | 立即进入锁定或退回巡线 |
| `STOP_LOCK` | 电磁铁保持开启，停车 200 ms，抑制惯性并继续看目标 | 目标仍有效则进入接近 |
| `APPROACH` | 电磁铁保持开启；根据目标横向误差差速转向，随目标框变大降速 | 连续 100 ms 看不到目标，或 7.5 s 超时 |
| `FINAL_CREEP` | 以 11 RPM 直行 2 s，不再依赖视觉 | 时间到后按“已吸住”处理并开始倒放 |
| `PICKUP_SETTLE` | 仅保留旧状态编号兼容，不再由正常流程进入 | 立即进入倒放 |
| `BACKTRACK` | 将离线期间记录的左右轮命令反号并逆序执行 | 回到接近原循迹线的位置 |
| `REACQUIRE_LINE` | 按离线前方向左右扫线 | 连续 30 ms 识别到线；3 s 超时进入故障 |
| `LINE_FOLLOW_CARRY` | 带球继续使用原有循迹逻辑 | 15 s 保持时间结束或人工释放 |
| `FAULT` | 电机停车；未持球时关闭电磁铁 | 发送停止命令后重新启动 |

轨迹每 20 ms 记录一次，容量 512 项，可覆盖约 10.24 s。当前“原路退回”是速度命令倒放，不是基于里程计的绝对路径复现；轮胎打滑、碰撞和地面差异会产生误差，因此最后仍使用灰度传感器扫线兜底。

15 s 电磁铁计时从 2 s 盲走结束、软件判定“已吸住”时开始。倒放、重新捕线、恢复巡线甚至收到停车命令期间计时仍继续；计时结束自动关闭电磁铁。人工发送释放命令仍会立即关闭。

正常巡线或带球巡线中，如果八路灰度全部为白色，左右轮固定为 `32/-18 RPM`，持续大幅向右转；任一通道重新检测到黑线后立即恢复原巡线算法。寻球接近、轨迹倒放和重新捕线状态不调用该全白分支，因此两套逻辑相互独立。

## 4. 故障与降级

- 视觉帧超过 200 ms 未更新：目标失效。
- 接近时目标短暂丢失：先保持 11 RPM 直行；连续丢失 100 ms 后进入完整的 2 s 盲走。
- 2 s 盲走完成：无取球传感器，按时序假定吸取成功，开始 15 s 电磁铁保持计时并倒放。
- 接近超过 7.5 s 或轨迹缓存异常：关闭电磁铁并倒放已记录路径。
- 重新搜线超过 3 s：进入 `FAULT` 并停车。
- 无取球传感器：当前只按时序假定吸取成功，这是已知限制。
- HC-05 发送 `0` 会立即停车；若系统已认定持球，电磁铁仍保持吸合。停车后发送 `2` 才释放电磁铁。

## 5. 首轮必须标定的参数

| 参数 | 当前值 | 位置 | 标定目的 |
|---|---:|---|---|
| `CONTROL_CONFIDENCE_THRESHOLD` | 0.60 | `maixcam_ball_car/config.py` | 控制误检概率 |
| `BALL_CAR_MIN_WARNING_CONFIDENCE` | 50 | `ball_car.h` | 红框预警减速最低置信度 |
| `BALL_CAR_WARNING_SPEED_SCALE` | 1/3 | `ball_car.h` | 红框时对左右轮巡线输出的缩放比例 |
| `BALL_CAR_VISION_STEERING_SIGN` | +1 | `ball_car.h` | 确认画面左右与车轮转向一致 |
| `BALL_CAR_APPROACH_TURN_KP` | 0.18 | `ball_car.h` | 接近时横向纠偏强度 |
| `BALL_CAR_TARGET_LOST_CONFIRM_TICKS` | 10 | `ball_car.h` | 连续丢失目标 100 ms 后才启动盲走，过滤偶发红框 |
| `BALL_CAR_FINAL_CREEP_TICKS` | 200 | `ball_car.h` | 11 RPM 盲走 2 s 的前探距离 |
| `BALL_CAR_MAGNET_HOLD_TICKS` | 1500 | `ball_car.h` | 判定吸取后保持电磁铁 15 s |
| `LINE_FOLLOW_WHITE_RIGHT_LEFT_RPM` | 32 | `line_follow.h` | 全白区域向右转时左轮速度 |
| `LINE_FOLLOW_WHITE_RIGHT_RIGHT_RPM` | -18 | `line_follow.h` | 全白区域向右转时右轮速度 |

首次只改一个参数并重复测试。原有循迹速度、急弯和速度 PI 参数已经通过实车验收，不应与视觉参数同时大幅修改。
