# 循迹寻球小车架构与状态机

## 1. 功能边界

当前方案只使用两块计算控制设备：

```text
MaixCAM：钢珠检测、时序跟踪、主目标选择
    │ UART 115200，目标坐标/大小/置信度
    ▼
MSPM0G3507：状态机、循迹、接近控制、速度闭环、电磁铁控制
    │
    ├─ TB6612 + 双编码器电机
    ├─ YB-MVX05 八路灰度
    └─ 外置 MOSFET + 电磁铁
```

MaixCAM 不直接控制电机。它只发送视觉测量值，所有安全状态、运动决策和执行都由 MSPM0G3507 完成。这样即使视觉帧丢失或应用退出，MSPM0 也能在 200 ms 超时后判定链路失效。

## 2. 软件模块

### MSPM0G3507

| 文件 | 职责 |
|---|---|
| `car_app.c/.h` | 顶层初始化、10 ms 调度、命令处理、状态整合 |
| `ball_car.c/.h` | 寻球取球状态机和轨迹记录/倒放 |
| `vision_uart.c/.h` | UART2 中断接收、环形缓冲、链路超时与状态回传 |
| `vision_protocol.c/.h` | 帧解析、CRC8、数据编解码 |
| `magnet_driver.c/.h` | PB10 外置 MOSFET 逻辑控制 |
| `line_follow.c/.h` | 已验收的灰度循迹逻辑 |
| `line_sensor.c/.h` | 八路灰度读取与位置误差 |
| `speed_pid.c/.h` | 双轮速度 PI |
| `tb6612.c/.h` | 双路电机驱动 |
| `wheel_encoder.c/.h` | 双编码器四倍频计数 |

`main.c` 只调用 `car_app_init()` 和 `car_app_run()`，不承载具体业务逻辑。

### MaixCAM

| 文件 | 职责 |
|---|---|
| `main.py` | 相机、模型推理、显示、UART 调度 |
| `ball_tracker.py` | 候选过滤、多帧匹配、稳定目标选择 |
| `vision_uart.py` | MaixPy UART1 初始化、发送目标、接收小车状态 |
| `vision_protocol.py` | 与 MSPM0 完全对应的二进制协议 |
| `config.py` | 模型阈值、跟踪、接近判断和 UART 参数 |

视觉端将“显示阈值”和“控制阈值”分开：达到 50% 的目标可以画框，但只有达到 70% 且连续稳定 5 帧的目标才可控制小车。

## 3. 状态机

控制周期为 10 ms。

| 状态 | 主要行为 | 退出条件 |
|---|---|---|
| `IDLE` | 电机停车；若未持球则关闭电磁铁 | 收到启动命令并完成 3 s 延时 |
| `LINE_FOLLOW` | 使用原有 70 RPM 自适应循迹 | 稳定视觉目标出现 |
| `TARGET_CONFIRM` | 继续循迹并二次确认目标 | 连续 100 ms 合格则停车；失效则回循迹 |
| `STOP_LOCK` | 停车 200 ms，抑制惯性并继续看目标 | 目标仍有效则进入接近 |
| `APPROACH` | 根据目标横向误差差速转向；随目标框变大降速 | 框高达到画面 30%；目标丢失或 7.5 s 超时 |
| `FINAL_CREEP` | 提前打开电磁铁，以 11 RPM 前进 350 ms | 时间到 |
| `PICKUP_SETTLE` | 停车并维持电磁铁 500 ms | 按时间假定吸取完成 |
| `BACKTRACK` | 将离线期间记录的左右轮命令反号并逆序执行 | 回到接近原循迹线的位置 |
| `REACQUIRE_LINE` | 按离线前方向左右扫线 | 连续 30 ms 识别到线；3 s 超时进入故障 |
| `LINE_FOLLOW_CARRY` | 带球继续使用原有循迹逻辑 | 停车或人工释放 |
| `FAULT` | 电机停车；未持球时关闭电磁铁 | 发送停止命令后重新启动 |

轨迹每 20 ms 记录一次，容量 512 项，可覆盖约 10.24 s。当前“原路退回”是速度命令倒放，不是基于里程计的绝对路径复现；轮胎打滑、碰撞和地面差异会产生误差，因此最后仍使用灰度传感器扫线兜底。

## 4. 故障与降级

- 视觉帧超过 200 ms 未更新：目标失效。
- 接近时目标短暂丢失：按最后一次横向误差低速旋转搜索，宽限约 300 ms。
- 目标持续丢失、接近超时或轨迹缓存异常：关闭电磁铁并倒放已记录路径。
- 重新搜线超过 3 s：进入 `FAULT` 并停车。
- 无取球传感器：当前只按时序假定吸取成功，这是已知限制。
- HC-05 发送 `0` 会立即停车；若系统已认定持球，电磁铁仍保持吸合。停车后发送 `2` 才释放电磁铁。

## 5. 首轮必须标定的参数

| 参数 | 当前值 | 位置 | 标定目的 |
|---|---:|---|---|
| `CONTROL_CONFIDENCE_THRESHOLD` | 0.70 | `maixcam_ball_car/config.py` | 控制误检概率 |
| `CLOSE_BOX_HEIGHT_RATIO` | 0.30 | `maixcam_ball_car/config.py` | 进入镜头盲区前切换低速盲走 |
| `BALL_CAR_VISION_STEERING_SIGN` | +1 | `ball_car.h` | 确认画面左右与车轮转向一致 |
| `BALL_CAR_APPROACH_TURN_KP` | 0.18 | `ball_car.h` | 接近时横向纠偏强度 |
| `BALL_CAR_FINAL_CREEP_TICKS` | 35 | `ball_car.h` | 电磁铁前探距离 |
| `BALL_CAR_PICKUP_SETTLE_TICKS` | 50 | `ball_car.h` | 吸取建立时间 |

首次只改一个参数并重复测试。原有循迹速度、急弯和速度 PI 参数已经通过实车验收，不应与视觉参数同时大幅修改。
